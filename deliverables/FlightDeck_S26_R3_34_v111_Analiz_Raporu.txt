GÜÇLÜ YÖNLER
─────────────

İki Katmanlı Depolama
  • localStorage : Ayarlar ve operasyonel durum (~25+ anahtar)
  • IndexedDB    : Charter/REZ verisi — SummerTourFlightDB v2 (5–60 MB, 5 object store)
Bu ayrım mantıklı; büyük binary blob'lar IDB'de, hızlı erişim gerektiren config
localStorage'da.

Snapshot Sistemi
10 snapshot slot, zaman damgalı geri dönüş — iyi tasarım.

KRİTİK AÇIKLAR
───────────────

D1 — JSON Yedek IndexedDB İçermiyor (VERİ KAYBI RİSKİ)
exportStateBackup() yalnızca localStorage anahtarlarını dışa aktarıyor.
IndexedDB şunları içeriyor ve yedeklenMİYOR:
  • current_raw  : Ham Excel verisi
  • current_rez  : Rezervasyon verisi
  • 10 snapshot  : Geri dönüş noktaları
  • S25 referans : Geçmiş sezon karşılaştırma verisi (5–60 MB)

Kritik kayıp senaryosu:
  1. Kullanıcı "Yedek İndir"        → JSON dosyası kaydedilir (IDB YOK)
  2. "Tüm Veriyi Sıfırla"           → IDB temizlenir
  3. "Yedek Yükle"                  → Yalnızca localStorage geri gelir
  4. SONUÇ: Tüm uçuş ve REZ verisi kalıcı olarak kaybolur.

D2 — Non-Atomic IDB Yazma
saveSnapshot() (satır 19553–19568) dört ardışık dbSet() çağrısı yapıyor,
tek transaction değil. İkinci yazma sırasında çökme → yarı yazılmış, tutarsız
snapshot.

D3 — Schema Migrasyon Yok
IndexedDB onupgradeneeded (satır 19487) v1→v2 migrasyon mantığı içermiyor.
Mevcut v1 verisi olan kullanıcı v2'ye geçince veri kaybolabilir.
